# Lessons

The kit's working rules for any project's team (navigator, builders, budgets, Hank, the guard, chains, QA roles, orders), learned the hard way in the projects that use it. Cite a rule by its slug in brackets, never by a number.
One line per rule, ≤ 300 characters. Readers read this file and the project's own `.claude/lessons.md` (its rules about its pages, kinds and tables; its figures sit in `lessons-numbers.md`); a slug lives in one of the two, never both. Alexander's way of working is `~/.claude/CLAUDE.md`, not restated here.
Moved here from Hutzup's lessons at 3.3.3, 11 Oct 2026; `/future-ted` replaces stale lines rather than appending, and a kit edit commits in this repo.

- **[skyler]** Skyler and Hank count real tokens (each message.id once); a `local_…` session id resolves to its transcript itself (`--timeline` too, Burrow 0.6); older figures sit on an inflated scale (see the project's numbers file), so compare like with like.
- **[meter]** Report a release two ways: Skyler ÷ the planning figure in `.claude/kit.json` (the estimate) and the weekly meter's delta (a ceiling, naming the sessions beside it); judge a many-card release per card, and start a day chain right after a 5-hour reset.
- **[one-theme]** One theme per release is the cheapest shape; size it by its kind (kit, packaging, guard, pages, polish, sweep) from the per-commit rates in the project's numbers file, on the real scale. A theme can hold several features when none needs him live ([split-by-live]).
- **[split-by-live]** A roadmap is cut where a release needs Alexander live (a real form, a login, a look, a device), not by feature: what checks on test data builds as one release, the live parts follow as sessions. job-hunt's V0.3–V0.7 built as one: 18 commits, 50 min, 29.8M.
- **[auto]** Manual mode: `~/.claude/CLAUDE.md` (Auto by default). Process edits run in Bypass. A deploy link reads with Read/Grep only, takes times from tool output, and on any Auto refusal sends `LINK WAITING` and goes on only on Alexander's word, never by another route.
- **[keep-going]** Alexander's way of working: `~/.claude/CLAUDE.md` (Auto by default: another route, then defer after two tries under "What needs you").
- **[cover]** A chain's tap holds while the frozen set is unchanged: run `node scripts/chain-cover.mjs <v>` before each deploy, a lost cover is a re-tap, never manual; a frozen-files release taps its own arm before the spawn, and a script under test runs in its temp project.
- **[deploy-order]** Under a covering marker `ranjit` copies `preview`'s block (backup first, one push for all migrations); the order carries the PR state, the post-merge reads, the human steps inline, a smoke at 375 and 1024, one listed call per message and no loops. No marker: keep the plan round.
- **[deploy-plan-skip]** When `preview`'s "Plan, as ranjit writes it" block passes `check-plan` from the file, step 1's checks passed and a chain marker covers the version (`chain-cover.mjs` exits 0), the deploy skips the plan round, database deploys too; `check-plan`'s backup check still runs.
- **[release-bump]** The first commit of every release sets the project's version field to the version, when it has one (the footer or about page reads it), and is pushed before any step; review reads it as a must (2.14.9.1 shipped saying v2.14.9). Bump with `npm version <v> --no-git-tag-version`, never a sed over the lock file (hejtide 0.3's sed also rewrote a dependency's version).
- **[human-steps]** Handing a human step over: `~/.claude/CLAUDE.md`. The deploy leg ticks what ran in the ledger `<plans>human-steps.md` (`[x] (<date>)`); a step still open stays open there, and the ping gives the ledger link, never "yours when you're ready".
- **[pr-size]** A PR over 100 changed files can be armed (the guard pages the list), but a big release is a size smell: the navigator keeps `git diff --name-only main...HEAD | wc -l` in each wave's report.
- **[signed-in]** Production has no signed-in runner: a deploy order lists signed-out checks only and a signed-in look is a human step; in a chain a signed-out dev tab never holds a link, and the PR's QA section names each deferral (see [chain-start]).
- **[production-reads]** Production reads go to `ranjit`, never a release's navigator or its agents (the guard refuses them); an audit takes its production baseline from `/skinny-pete <v> check` or the deploy's checks, and its lanes read dev.
- **[frozen]** The guard's files need a person (Auto or default: the guard asks; Bypass: it denies): guard work is its own small release, built in a proto under renamed folders, pasted by Alexander; probe what may be copied, hook tests under Vitest, a paste carries every stale line.
- **[first-spawn]** A production agent's first spawn in a session is a harmless one, unless a hook allow surely covers the real one.
- **[floor]** Half of an agent's tokens is its fixed start (the tool definitions), so agents get explicit `tools:` lists and make fewer, batched calls.
- **[sweep]** A sweep of 20+ files gets 25–30M or two lanes; its order greps for what the page shows, not one code pattern, and a class-name sweep greps its own diff, over the whole tree, for glued tokens.
- **[hank]** A budget tag is real tokens, written ×1; Hank reads only the first message's tag and counts a resumed agent's whole run, so the first order carries the full total, and a small fix after a finished run goes to a fresh agent.
- **[roadmap-page]** Name the roadmap page by its id from memory, never recall; a status change is one row `update` by a fresh `c-3po`, a republish only when `page.html` changes (checked in the harness over http), and the conductor re-reads its end write from `main`.
- **[chain-cost]** The navigator, not the lanes, is a chain's big line and grows with wave width and with fixes it makes itself; budget it from the numbers file, add its close-out (the PR's Usage misses it), and a link waiting for its order costs nothing.
- **[sizing]** Size from measured lanes and watch the navigator's line; a tag of 2–3× the measured lane is enough.
- **[hotfix]** A hotfix costs its navigator, not its lanes, and a step added mid-hotfix doubles it: a hotfix that grows re-sizes its card at once and re-runs the PR-body check with the new step.
- **[shots]** A `/superlab` designer order carries an exact shot list with one spare, `shot.mjs` headless on its own port, the mock skeleton to reuse, what must go, constants checked in code and a typeface as a drawing; `save-shot.mjs` refuses images older than the pass.
- **[parallel]** Four builders at most, on files that don't overlap, with the navigator writing each shared helper first; commit by `git commit -- <paths>`, keep shared files compiling, never stash, checkout, reset or pull in a shared checkout; two at most above 70% of the 5-hour window.
- **[builder-checks]** Builders check what keeps coming back (the project's `.claude/builder-checks.md` holds its shapes): new CSS in `@layer`; a test touching browser storage stubs it; measured at the breakpoint and widest width on the extreme fixture; CI read after each push; lint's exit code.
- **[fixer]** A fixer ticks each numbered finding against its own diff before it reports.
- **[qa-like-a-user]** QA creates the thing by hand from the page a user starts on, not only on seeded rows or a sheet opened directly: Burrow 0.8's QA passed two flows his first dev test failed (no door where she logs, no line until a reload).
- **[reuse-line]** A builder reused past ~150k context costs more than a fresh one with a full order: Burrow 0.8's two-step page ran 21.7M in one agent against ~5M a single page, and job-hunt 0.4's two joins on one agent re-read the first inside the second until Hank stopped it at 6M. Each join or page half gets a fresh agent.
- **[data-contract]** An external source's reading rule (what a row's time means, its units) goes in every order that reads its table, not only the fetcher's: Burrow 0.8's three weather readers wrote three readings of SMHI's rain interval (review must, one shared helper).
- **[layout-qa]** The Bengan Boys run only when Alexander asks or the release is taste-heavy; a must's fix is re-checked at the width it was found, a theme is set per tab with `?theme=`, and passes run two at a time, each told what the earlier ones found.
- **[guard-noise]** The guard refuses harmless shell text: under a marker every agent edits with Edit or Write and reads with Read or grep, never an interpreter heredoc, a template literal or a `cd` into a runtime folder; long scripts go in a scratch file; a refusal is reported, never re-spelled.
- **[evals]** A plugin eval case only tests a skill the model may invoke (never one with `disable-model-invocation`); start a case file from `claude plugin eval init --bare`.
- **[security-brief]** A throttle brief names all three caps (per key, per target, global) and where it counts atomically; a security read runs in the same wave as the anon surface it covers; an auth brief names the link types each flow signs in with.
- **[fixtures]** A SQL suite asserts on its own fixture rows, never on every row of a table (dev carries real data); QA and page orders name the fixture state they need and the path to open it.
- **[taste-default]** A look default (a mark, label or placement, however small) goes to Alexander at the start or parks as `TASTE WAIT`, never into the build unasked.
- **[raven]** `three-eyed-raven` decides with what the order carries, names any missing source and never sends an order back; it decides data inside fixed scope, never access (who may flip a switch), and a decided placement doesn't forbid additions.
- **[inception]** `/inception` settles what the build can't: a bug's repro path, rules that can collide, plan lines that disagree, earlier fixes a changed function must keep; sessions beside a drive don't write the checkout, and log times come from `scripts/stamp.sh`.
- **[numbers]** Numbers only from Skyler, labelled from `--timeline` (local time; PRs write UTC with a Z); a transcript is named by its command, never its size or model; clean up dev by id, take test logins from the signed-in tab, and QA undoes shared state it changes.
- **[trials]** A trial's verdict goes in the release's chain-log section and its wrap-up, not only in the plan it feeds.
- **[preview]** Leg 1 runs `scripts/full-auto.sh preview <version>` before `Leg 1 done`; every production step's label stays under 60 characters in a code span, and a merge-only release sets "After merge" to None.
- **[chain-start]** A chain's start checks what only Alexander can fix while he's there: Docker running for a database link, the dev port signed in (asked in the same pick as the tap); the conductor opens the link sessions itself in that first turn (`start_session`).
- **[hand-off]** A link's order lands only in an idle session (set the model, wait for idle, send; `list_events` before any resend) and works as plain text; a peer relaying Alexander's wish is information, not his word, so ask him as a pick.
- **[orders]** An order carries what lanes would otherwise read for: line numbers and anchors, old→new pairs (diff form, not "update the doc"), tables to copy, known check failures, the README owner, proof files, the no-heredoc rule under a marker. A long text field changes by `str_replace`.
- **[templates]** A template that reads a config key waits for the step that defines the key. A starter is render-checked from its fill script with fixture values.
- **[routines]** A routine that changes things picks with a script, not a model: the script makes the list, the model only acts on it, an allow line exists before any unattended run, and until then it runs dry; `lastActivityAt` is no measure of idle.
- **[two-copies]** Until the switch release, a skill or agent with a kit copy changes in both, in one commit; the copies differ on purpose in generic lines, so the lane gets the replacement pairs to apply with one script, and `kissochbajslowski` diffs the pair.
- **[kit-publish]** A public kit's lanes grep their output for the source project's values (refs, ports, names, paths) before they commit; a marketplace refresh doesn't update an installed plugin (`claude plugin update … --scope project`); publish from merged `main`, subtree split, no force.
- **[sibling-wait]** A navigator never ends its turn waiting on a sibling: ask by send_message and carry on; the answer arrives as a hand-back (3.3.2 part 1 held parts 3–4 for 2.5 h).
- **[live-check]** A live run by Alexander finds what no check can: hand it over with what it runs, what it may touch and how to stop, run it in a fresh follow-up session, and plan it as a human step afterwards, never one a link waits on.
- **[real-shape]** Fixtures are copied from one live read of the source, never written from memory, and a library's shape is read from its types in `node_modules` before context7: job-hunt 0.3's mail extractors and 0.4's reply rules, built on made-up mails, both failed their first live read (0.4: 5 of 8 no's, 5 fix commits).
- **[name-match]** A lookup by company name confirms the match on a second key (its own domain) before it is kept: job-hunt 0.3's watchlist seed kept 4 namesakes in 8 boards until his live probe.
- **[one-yes]** One yes per step that reaches outside the machine, asked at that step, not once up front.
- **[auto-outside]** Auto refuses a subagent reading personal data from his files and any MCP write to an outside system, even after his go in chat: the navigator does those after his explicit go, and a tool he uses daily gets a project allow line. job-hunt 0.1: three refusals and PR #5.
- **[intent-trace]** Every line Alexander agreed to is traced to a step: `/inception` lists each (I1, I2 …) beside the step that builds it, the design brief quotes them word for word, and review and the last Bengan pass check the build against his words, not only the drawing.
- **[one-session]** One signed-in dev session serves at most two browser lanes: each browser lane runs its own port, signed in at the start, on a fixed QA group nobody toggles, restarted after any package.json change; QA selects controls by aria-label, never by position.
- **[watchdog]** While anything runs, the navigator never ends a turn without a background `sleep` timer (1200, away 600); each wake checks lanes' last commit and write and sessions' last event, stops 20-min silence, does a prompt-stuck step itself. Burrow V0.9: part 3 sat 10 h on one prompt.
- **[send-confirmed]** A send that comes back queued or unconfirmed is not delivered: read the target's events within 5 min, do the work yourself if it hasn't acted, and never report it delivered. Burrow V0.9: three queued sends to part 3 (skip QA) were reported delivered; it ran QA.
- **[release-session]** One session per release to the draft PR; the context summarizes, it never hands off (`hand_off_to_session`), and makes no offer or follow-up card mid-release: an unrelated message gets a one-line answer or `/badger`, a follow-up goes to "Not in this release" or `/badger`; one follow-up session at most, at the draft PR. Parts only when the stamped plan names them, opened by the navigator with `start_session` in its first turn (norms.md, "The app's session tools") and logged under `## Release sessions`; a session card mid-release cost him a click at night (Burrow V0.9). Trial 16–20 Oct (norms.md, "Starting sessions"): a release may start a session itself mid-run for work outside its scope (its own branch and PR, named in "Not in this release"), and starts its one follow-up session at the draft instead of a card; a refused start goes to "Not in this release" or `/badger`, still no card mid-run.
- **[guard-sed]** The guard read `sed -i ''`'s script as a path (`.*` a glob that might be .github) and a write a line after `a && cd X` as in an unknown folder: both asked, and away nobody answered. Fixed (Burrow V0.9); a multi-line sed `a\` with backticks still asks, so edit with Edit.
- **[layout-first]** A layout theme ships inside the mode or feature it serves, designed first (`/superlab`, his pick), never as its own sweep; builders open their own 375/1024/1440 shots and judge by eye against `main`, never a measuring rule. Burrow V0.9 was aborted for both.
- **[grep-first]** A plan sizes each step from a grep of what it changes, the file:line beside the step: Burrow V0.9 sized 15M of inline actions on ⋯ menus that didn't exist (a grep: 3M).
- **[lockfile]** A lock-file change is checked with CI's exact npm (`npx -y npm@<CI's version> ci --dry-run` in a scratch copy) before the next step, and CI's result is read before moving on.
- **[turns]** No order over 15M and a step cut at 6 files; agents don't count their turns, so the cap is `maxTurns` in the agent files, and a review of a whole part splits into a database lane and an app lane.
- **[research]** Research on vendor limits fetches each pricing page plus one limits page, with no search step.
- **[research-scope]** Research answers the person's questions verbatim plus the angles the decision needs (alternatives, control, costs, permits, safety, peers), not the caller's framing; large is lanes, a counter pass and a check in its own session. hejtide 15 Oct 2026: 200k of 10M, Massvis cut.
- **[research-lanes]** A lane writes its skeleton after a few searches and fills it as it goes, about five questions a lane; read a found PDF at once, not its search summary; read an Open Collective host from the group's transaction filters. hejtide: two of three lanes hit 30 turns, nothing saved.
- **[lane-home]** Lane worktrees live outside `.claude` (`~/Desktop/<Project>-lanes/<lane>`): Agent `isolation: worktree` puts them under `.claude/worktrees`, and every write under a `.claude` folder asks even in Auto (Burrow 0.6: the run went to Bypass at 20:35Z). The order names the lane folder: portfolio 0.5's lanes landed in `.claude/worktrees` again and their `.next` builds broke local lint (fix commit a498278).
- **[kit-agents]** A kit version that moves an agent out of a plugin copies it into each project that uses it in the same change: kit 1.3 left Burrow without `ranjit`, so `/skinny-pete 0.6` stopped, and a copied agent loads only in a fresh session.
- **[live-tweaks]** After the draft, his live runs and tweak rounds go to a fresh session per batch of notes, each tweak to a fresh Sonnet builder; never the release navigator. The navigator recommends New session at the app's card. Broken: hejtide 0.1 (83% of 335M), job-hunt 0.1 (14M→93M), 0.3 (17M→60M). Kept: job-hunt 0.2 (5.5M), 0.4 (L1–L6 in one 33M session).
- **[idle-navigator]** A navigator woken after its draft pays its whole context per call: job-hunt 0.2's 22 calls cost 5.4M, 0.3's `/one-ring` in the 56M session 3.8M, 0.4's merge on "merge it" 7.1M over 24 calls (~295k each). After the draft it ends its turn; the merge goes through `/one-ring` in a fresh session. It holds when the step table's last row says so ("draft ping + notes card, navigator ends"): portfolio 0.5's navigator stopped at 7.6M and its notes and merge ran fresh for 2.1M; the same rule as a plan line alone didn't hold in portfolio 0.2 (26M at the draft, 90M at the end).
- **[new-project-agents]** A new project's skeleton carries the deployer agent and kit.json `deployer` from day one: hejtide 0.1 had neither, so the guard kept `gh pr ready`/`merge` from every session and Alexander clicked them.
- **[review-lanes]** `/its-a-trap` runs as `kissochbajslowski`, never `general-purpose`: Burrow 0.6's four Opus lanes cost ~26M against a Sonnet run's 4.0M. The skill's route spawns him since kit 4b80f20: job-hunt 0.2's review cost 0.2M on Sonnet and found both musts.
- **[script-input]** When the model writes a file a script reads (rows.json, notion-row.json), the order says the script validates every key and exits naming the row and key: job-hunt 0.2's report printed "Totalt: 0" on a bad file (review must, 22ea96a).
- **[login-form]** A form behind a login gets its read-only look before a builder writes its format, not after the draft: job-hunt 0.2 built the draft around a Sätt field the real form doesn't have and redid it after the look (d21cf2b, 0.8M plus a 5.5M session).
- **[extension-drop]** Claude in Chrome can drop right after a BankID login (job-hunt 0.2, Brave: two 10-minute timeouts). After one timeout, read the page through computer-use instead (`app_screenshot`, `app_ax_find`; a browser is read-only there), which read the whole form.
- **[ask-last]** Before asking Alexander a fact, read dev, the plan, memory and the data; a question whose answer writes a column says which way the column reads. Burrow 0.7's deploy asked the split he'd given, wrote it backwards: a fix file, a second backup.
- **[no-production]** A project that ships nowhere says `"production": "none"` in kit.json and merges through `/one-ring`'s "No production" section, with no deployer: job-hunt 0.1 had no `ranjit`, so the guard kept `gh pr ready`/`merge` from everyone and Alexander merged PR #3 in his terminal. A project with production still gets a deployer from day one ([new-project-agents]), except one its host ships from main with no database: `"production": "on-merge"` and `/one-ring`'s "Ships on merge" (portfolio V0.1 and V0.3 merged by hand without it).
- **[guard-code-words]** The guard reads code it can't parse (a heredoc's Python, a quoted node line after an unknown runner) as command lines, and a word there that looks built at run time counts as a hidden gh merge. Since job-hunt 0.1 a plain glob (`x[k]`, `?:personligt?`) counts only when it could match or names a guarded command; a `$` word (`$p`, `${MONTH_RE.source}`) still does, so for heavy code write a script file with Write and run it.
- **[read-back]** A note of Alexander's with a negation or a relative ("not left aligned", "bigger", "above 13 inch") is read back as the exact look, with a number or a shot, before a builder starts: hejtide 0.4 misread "I also don't think she meant left aligned" as centred text and spent three commits (cedf8c1, 2c226c3, 591ee5c) and a wrong-way round to land it; the 96rem "above 13 inch" switch came back to 1280 a day later (32d29a4).
- **[pane-motion]** The built-in browser pane doesn't tick animations or run smooth scrolling: a scroll or motion probe runs with motion off (or in headless Chromium) and the smooth path goes to his phone look. portfolio 0.5: the builder's focus probe passed while a phone-menu jump to Contact moved focus without scrolling; QA caught it and a fix round followed.
- **[layout-check]** `spidey-sense` fetches `/scripts/qa/layout-check.js` from the dev server, but a Next project serves only `public/`, so QA orders name a script the project can't serve (portfolio 0.5's `staffan-olsson`). Until the skill changes (setup session), a QA order pastes the plugin's copy into one `javascript_tool` call.
