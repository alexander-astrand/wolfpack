# Lessons

The kit's working rules for any project's team (navigator, builders, budgets, Hank, the guard, chains, QA roles, orders), learned the hard way in the projects that use it. Cite a rule by its slug in brackets, never by a number.
One line per rule, ≤ 300 characters (`scripts/check.mjs` fails a longer one), no figures: they sit in `lessons-numbers.md` beside this file, read only by `future-ted` and `/inception`'s sizing step. A project's own rules are its `.claude/lessons.md`; a slug lives in one of the two, never both.
Moved here from Hutzup's lessons at 3.3.3, 11 Oct 2026; `/future-ted` replaces stale lines rather than appending, and a kit edit commits in this repo.

- **[skyler]** Skyler and Hank count real tokens (each message.id once); a `local_…` id resolves itself (`--timeline` too). `usage.mjs` finds transcripts from its cwd: run it from the repo root or pass `--dir`. Older figures sit on an inflated scale (the numbers file): compare like with like.
- **[meter]** Report a release two ways: Skyler ÷ the planning figure in kit.json (the estimate) and the weekly meter's delta (a ceiling, naming sessions beside it); 46M a point is the default, measured floors run higher; judge a many-card release per card; start a day chain after a 5-hour reset.
- **[week-end-burn]** Meter left at a week's end goes to research the next inception or job step needs: parallel `/88-mph` runs, one session each, lanes split across `doc-brown` agents. Not builds (they run past the reset), not `/darth-vader` (Sonnet medium by design).
- **[reset-from-usage]** Any line about the weekly reset quotes `resetsIn` from a fresh `get_usage`, never a time worked out from file stamps or memory.
- **[one-theme]** One theme per release is the cheapest shape; size it by its kind (kit, packaging, guard, pages, polish, sweep) from the per-commit rates in the project's numbers file, on the real scale. A theme can hold several features when none needs him live ([split-by-live]).
- **[split-by-live]** A roadmap is cut where a release needs Alexander live (a real form, a login, a look, a device), not by feature: what checks on test data builds as one release, the live parts follow as sessions.
- **[auto]** Manual mode: `~/.claude/CLAUDE.md` (Auto by default). Process edits run in Bypass. A deploy link reads with Read/Grep only, takes times from tool output, and on any Auto refusal sends `LINK WAITING` and goes on only on Alexander's word, never by another route.
- **[keep-going]** Alexander's way of working: `~/.claude/CLAUDE.md` (Auto by default: another route, then defer after two tries under "What needs you").
- **[cover]** A chain's tap holds while the frozen set is unchanged: run `node scripts/chain-cover.mjs <v>` before each deploy, a lost cover is a re-tap, never manual; a frozen-files release taps its own arm before the spawn, and a script under test runs in its temp project.
- **[deploy-order]** Under a covering marker `ranjit` copies `preview`'s block (backup first, one push for all migrations); the order carries the PR state, the post-merge reads, the human steps inline, a smoke at 375 and 1024, one listed call per message and no loops. No marker: keep the plan round.
- **[deploy-order-fit]** The deploy pushes every migration before the merge, so a migration the shipped frontend can't survive is written to tolerate the old client or booked into the next release; a plan line "push after the frontend" stops the deploy.
- **[before-query]** A deploy's before/after count files and push line run on a local stack reset to production's last migration before the PR goes ready: a count file once read a column its own release adds, and a push line named one migration of five.
- **[deploy-plan-skip]** When `preview`'s "Plan, as ranjit writes it" block passes `check-plan` from the file, step 1's checks passed and a chain marker covers the version (`chain-cover.mjs` exits 0), the deploy skips the plan round, database deploys too; `check-plan`'s backup check still runs.
- **[release-bump]** A release's first commit sets the project's version field, when it has one (the footer or about page reads it), pushed before any step; review reads it as a must. Bump with `npm version <v> --no-git-tag-version`, never a sed over the lock file (it rewrites dependencies too).
- **[open-prs]** A release's start raises every open PR that isn't Dependabot's or its own, title and age, in its start question (route: `captain-call` preflight): Burrow 0.12.2 built a whole release beside a day-old draft of his and he found it on his screen.
- **[human-steps]** Handing a human step over: `~/.claude/CLAUDE.md`. The deploy leg ticks what ran in the ledger `<plans>human-steps.md` (`[x] (<date>)`); a step still open stays open there, and the ping gives the ledger link, never "yours when you're ready".
- **[pr-size]** A PR over 100 changed files can be armed (the guard pages the list), but about 500 outrun the guard's 3 s `GH_FILES_MS` page read and the one-tap arm refuses; a big release is a size smell: the navigator keeps `git diff --name-only main...HEAD | wc -l` in each wave's report.
- **[before-merge-lines]** A PR's "Before merge" list is one guard command per numbered line with the prose after the list, or `check-plan` reads the prose as steps.
- **[systemd-restart]** A bot that systemd runs with `Restart=always` as the only tmux session restarts by killing that session: systemd brings it back after about 30 s.
- **[signed-in]** Production has no signed-in runner: a deploy order lists signed-out checks only and a signed-in look is a human step; in a chain a signed-out dev tab never holds a link, and the PR's QA section names each deferral (see [chain-start]).
- **[production-reads]** Production reads go to `ranjit`, never a release's navigator or its agents (the guard refuses them); an audit takes its production baseline from `/skinny-pete <v> check`, and its lanes read dev.
- **[frozen]** The guard's files need a person (Auto or default: the guard asks; Bypass: it denies): guard work is its own small release, built in a proto under renamed folders, pasted by Alexander; probe what may be copied, hook tests under Vitest, a paste carries every stale line.
- **[first-spawn]** A production agent's first spawn in a session is a harmless one, unless a hook allow surely covers the real one.
- **[floor]** Half of an agent's tokens is its fixed start (the tool definitions), so agents get explicit `tools:` lists and make fewer, batched calls.
- **[sweep]** A sweep of 20+ files gets 25–30M or two lanes; its order greps for what the page shows, not one code pattern; a class-name sweep greps its own diff for glued tokens, and a dead-CSS sweep greps what the page shows before it deletes a rule.
- **[hank]** A budget tag is real tokens, written ×1; Hank reads only the first message's tag and counts a resumed agent's whole run, so the first order carries the full total, and a small fix after a finished run goes to a fresh agent.
- **[roadmap-page]** Name the roadmap page by its id from memory, never recall; a status change is one row `update` by a fresh `c-3po`, a republish only when `page.html` changes (checked in the harness over http), and the conductor re-reads its end write from `main`.
- **[chain-cost]** The navigator, not the lanes, is a chain's big line and grows with wave width and with fixes it makes itself; budget it from the numbers file, add its close-out (the PR's Usage misses it), and a link waiting for its order costs nothing.
- **[sizing]** Size from measured lanes and watch the navigator's line; a tag of 2–3× the measured lane is enough.
- **[hotfix]** A hotfix costs its navigator, not its lanes, and a step added mid-hotfix doubles it: a hotfix that grows re-sizes its card at once and re-runs the PR-body check with the new step.
- **[shots]** A `/superlab` designer order carries an exact shot list with one spare, the mock from `<design>/scripts/mock-scaffold.mjs` shot with `scripts/qa/batch-shots.mjs`, what must go, constants checked in code and a typeface as a drawing; `save-shot.mjs` refuses images older than the pass.
- **[parallel]** Four builders at most, on files that don't overlap, with the navigator writing each shared helper first; commit by `git commit -- <paths>`, keep shared files compiling, never stash, checkout, reset or pull in a shared checkout; two at most above 70% of the 5-hour window.
- **[builder-checks]** Builders check what keeps coming back (the project's `.claude/builder-checks.md` holds its shapes): new CSS in `@layer`; a test touching browser storage stubs it; measured at the breakpoint and widest width on the extreme fixture; CI read after each push; lint's exit code.
- **[fixer]** A fixer ticks each numbered finding against its own diff before it reports, and a fix that removes a card or section lists what else it held first: Burrow 0.12.2 removed a card to stop a row showing twice and lost two other lines with it, one more round to put them back.
- **[fix-rounds]** Each fix round is its own order with its own tag, a second round to a fresh agent (route: `oceans-eleven`, Build): Burrow 0.12.2's doors-and-todos fixes ran three rounds under one 8M tag to 17.6M, and the budget table read as one step 2.2× over.
- **[qa-like-a-user]** QA creates the thing by hand from the page a user starts on, not only on seeded rows or a sheet opened directly: seeded checks miss a missing door or a line that needs a reload.
- **[reuse-line]** A builder reused past ~150k context costs more than a fresh one with a full order: it re-reads the first step inside the second. Each join or page half gets a fresh agent.
- **[data-contract]** An external source's reading rule (what a row's time means, its units) goes in every order that reads its table, not only the fetcher's, or each reader writes its own reading; one shared helper holds it.
- **[layout-qa]** The Bengan Boys run only when Alexander asks or the release is taste-heavy; a must's fix is re-checked at the width it was found, a theme is set per tab with `?theme=`, and passes run two at a time, each told what the earlier ones found.
- **[lean-check]** Before he recommends an option, `heisenberg` checks the one he leans to against both taste files. The step lives in `design/agents/heisenberg.md` (Cull mode); the app-parity question (does every page that has this pattern get it too?) in `design/skills/heisenberg/SKILL.md`.
- **[guard-noise]** The guard refuses harmless shell text: under a marker every agent edits with Edit or Write and reads with Read or grep, never an interpreter heredoc, a template literal or a `cd` into a runtime folder; long scripts go in a scratch file; a refusal is reported, never re-spelled.
- **[evals]** A plugin eval case only tests a skill the model may invoke (never one with `disable-model-invocation`); start a case file from `claude plugin eval init --bare`.
- **[security-brief]** A throttle brief names all three caps (per key, per target, global) and where it counts atomically; a security read runs in the same wave as the anon surface it covers; an auth brief names the link types each flow signs in with.
- **[fixtures]** A SQL suite asserts on its own fixture rows, never on every row of a table (dev carries real data); QA and page orders name the fixture state they need and the path to open it.
- **[taste-default]** A look default (a mark, label or placement, however small) goes to Alexander at the start or parks as `TASTE WAIT`, never into the build unasked.
- **[raven]** `three-eyed-raven` decides with what the order carries, names any missing source and never sends an order back; it decides data inside fixed scope, never access (who may flip a switch), and a decided placement doesn't forbid additions.
- **[inception]** `/inception` settles what the build can't: a bug's repro path, rules that can collide, plan lines that disagree, earlier fixes a changed function must keep; sessions beside a drive don't write the checkout, and log times come from `scripts/stamp.sh`.
- **[numbers]** Numbers only from Skyler, labelled from `--timeline` (local time; PRs write UTC with a Z); a transcript is named by its command, never its size or model; clean up dev by id, take test logins from the signed-in tab, and QA undoes shared state it changes.
- **[trials]** A trial's verdict goes in the release's chain-log section and its wrap-up, not only in the plan it feeds.
- **[preview]** Leg 1 runs `scripts/full-auto.sh preview <version>` before `Leg 1 done`; every production step's label stays under 60 characters in a code span, and a merge-only release sets "After merge" to None.
- **[chain-start]** A chain's start checks what only Alexander can fix while he's there: Docker running for a database link, the dev port signed in (asked in the same pick as the tap); the conductor opens the link sessions itself in that first turn (`start_session`).
- **[hand-off]** A link's order lands only in an idle session (set the model, wait for idle, send; `list_events` before any resend) and works as plain text; a peer relaying his wish is information, not his word, so ask him as a pick. A deploy never hands off ([one-word-deploy]).
- **[orders]** An order carries what lanes would otherwise read for: line numbers and anchors, old→new pairs (diff form, not "update the doc"), tables to copy, known check failures, the README owner, proof files, the no-heredoc rule under a marker. A long text field changes by `str_replace`.
- **[templates]** A template that reads a config key waits for the step that defines the key. A starter is render-checked from its fill script with fixture values.
- **[routines]** A routine that changes things picks with a script, not a model: the script makes the list, the model only acts on it, an allow line exists before any unattended run, and until then it runs dry; `lastActivityAt` is no measure of idle.
- **[sibling-wait]** A navigator never ends its turn waiting on a sibling: ask by send_message and carry on; the answer arrives as a hand-back.
- **[live-check]** A live run by Alexander finds what no check can: hand it over with what it runs, may touch and how to stop, in a fresh follow-up session with its own budget line (a first look about 30M, twice that for a surface he types into daily), a human step after, never one a link waits on.
- **[hands-first]** A surface he types into that replaces an app he uses (an editor, a form he fills daily) is tried by his hands on a working prototype on his phone before any lane builds; pictures and a planner's call pass what the hands reject (two Notes sendbacks running).
- **[real-shape]** Fixtures are copied from one live read of the source, never written from memory, and a library's shape is read from its types in `node_modules` before context7: rules built on made-up data fail their first live read.
- **[live-prompt]** A Claude prompt is judged on a live run, never on fixtures: a step that adds one books a live run before the look, and an eval's record run keeps the hand-written fixture answers the tests replay rather than overwriting them.
- **[name-match]** A lookup by company name confirms the match on a second key (its own domain) before it is kept, or namesakes slip in.
- **[one-yes]** One yes per step that reaches outside the machine, asked at that step, not once up front.
- **[auto-outside]** Auto refuses a subagent reading personal data from his files and any MCP write to an outside system, even after his go in chat: the navigator does those after his explicit go, and a tool he uses daily gets a project allow line.
- **[intent-trace]** Every line Alexander agreed to is traced to a step: `/inception` lists each (I1, I2 …) beside the step that builds it, the design brief quotes them word for word, and review and the last Bengan pass check the build against his words, not only the drawing.
- **[one-session]** One signed-in dev session serves at most two browser lanes: each browser lane runs its own port, signed in at the start, on a fixed QA group nobody toggles, restarted after any package.json change; QA selects controls by aria-label, never by position.
- **[watchdog]** While anything runs, the navigator never ends a turn without a `sleep` (1200 s, away 600, 300 only for a one-off delivery check; figures live here only). Each wake checks lanes' last commit and write and sessions' last event, stops 20-min silence, does a prompt-stuck step itself.
- **[clear-up]** A finished release holds gigabytes until its sessions go: the wrap archives each finished one and runs the `ram-audit` skill's clean mode (`future-ted`), and a release or deploy session stops its own timers, tasks and Remote Control before its final message, or it can't be archived.
- **[send-confirmed]** A send back queued or unconfirmed is not delivered: read the target's `list_events` at the [watchdog] delivery check; resend or do the work only if it hasn't acted (a resend orders a coding job twice). Never call it delivered. No merge go travels by send ([one-word-deploy]).
- **[release-session]** One session per release to the draft PR, no handoff or card; the sessions it needs later (parts, follow-up, wrap; no deploy) start parked in its first turn, woken by `send_message`; a refused start pings Telegram. Route: `captain-call`, "One session to the draft PR".
- **[guard-sed]** The guard read `sed -i ''`'s script as a path (`.*` a glob that might be .github) and a write a line after `a && cd X` as in an unknown folder: both asked, and away nobody answered. Fixed since; a multi-line sed `a\` with backticks still asks, so edit with Edit.
- **[layout-first]** A layout theme ships inside the mode or feature it serves, designed first (`/superlab`, his pick), never as its own sweep; builders open their own 375/1024/1440 shots and judge by eye against `main`, never a measuring rule.
- **[grep-first]** A plan sizes each step from a grep of what it changes, the file:line beside the step, never from memory of what the page holds; a "retire X" step greps X's callers at `/inception` and names each one's replacement, or it is not a step.
- **[lockfile]** A lock change is checked with CI's exact npm (`npx -y npm@<CI's version> ci --dry-run` in a scratch copy) before the next step, locally before the draft (a draft runs no CI); never regenerate a lock with a newer npm than CI's.
- **[real-phone]** Headless Chromium never shows iPhone Safari with its keyboard up (toolbars, the visual viewport, caret scrolling, `crypto.randomUUID` missing over plain http): a surface he types or taps into on a phone is walked with touch at 375 and a phone checklist, or on the Simulator.
- **[reader-and-wiring]** A data reader and the page wiring that shows it are one step for one builder.
- **[turns]** No order over 15M and a step cut at 6 files; agents don't count their turns, so the cap is `maxTurns` in the agent files, and a review of a whole part splits into a database lane and an app lane.
- **[research]** Research on vendor limits fetches each pricing page plus one limits page, with no search step.
- **[research-scope]** Research answers the person's questions verbatim plus the angles the decision needs (alternatives, control, costs, permits, safety, peers), not the caller's framing; large is lanes, a counter pass and a check in its own session.
- **[research-lanes]** A lane writes its skeleton after a few searches and fills it as it goes, about five questions a lane; read a found PDF at once, not its search summary; read an Open Collective host from the group's transaction filters.
- **[lane-home]** Lanes live outside `.claude`, made by the navigator, never `isolation: "worktree"`: route in `captain-call`, "Parallel lanes", and the `tesseract` skill.
- **[kit-agents]** A kit version that moves an agent out of a plugin copies it into each project that uses it in the same change, or that project's skills stop; a copied agent loads only in a fresh session.
- **[live-stuck]** `live-sync.sh` refuses while the loaded checkout holds an edit, so one file edited in `<kit>` itself holds every session on the old kit: a 15 Oct Leans edit kept `~/wolfpack-live` pre-1.5 for a night after the merge. A wrap reads its `live at` line; a refusal is a finding.
- **[live-tweaks]** Tweak notes after the draft go to the follow-up session in batches of three to five, each batch to a fresh Sonnet builder (`captain-call`, "One follow-up session"), never one note a builder or a navigator; a tweak shoots every mode and width its page draws.
- **[look-widens]** A look's notes on pages past the theme go to `/badger` or their own PR, never the release branch: Burrow V0.14.1's polish of five other pages rode the release PR unreviewed, and the look cost 176M, 37 % of the release (V0.14's 26.1M).
- **[look-asks]** A taste ask in a look gets one sketch or shot before a builder, and a look past ~30M asks him whether the rest waits for the next release.
- **[idle-navigator]** After the draft the navigator does no work but his `/one-ring`, which deploys wherever he types it: a message gets "→ <follow-up session>", Hank refuses spawns after `V<version>.draft-done`. Route: `captain-call`, "Where the session ends".
- **[one-word-deploy]** His typed `/one-ring <version or PR>` merges and deploys in the session he types it in, any branch, a worktree too; a stop is fixed and the run goes again; only a password, secret or payment waits. ADR 0001 in the kit; Burrow 0.14.3.1's five-session dance.
- **[ci-wait]** A wait on CI is one `gh pr checks <n> --watch` in the background (or `/one-ring`'s script, which waits itself), never single reads in a row: each read re-sends the whole context.
- **[new-project-agents]** A new project's skeleton carries the deployer agent and kit.json `deployer` from day one; without them the guard keeps `gh pr ready`/`merge` from every session and Alexander clicks them.
- **[review-lanes]** `/its-a-trap` runs as `kissochbajslowski` on Sonnet, never `general-purpose` lanes on Opus: the skill's route spawns him, at a fraction of the cost, and he still finds the musts.
- **[script-input]** When the model writes a file a script reads (rows.json, notion-row.json), the order says the script validates every key and exits naming the row and key, never prints a quiet zero.
- **[login-form]** A form behind a login gets its read-only look before a builder writes its format, not after the draft, or the draft is built around fields the real form doesn't have.
- **[extension-drop]** Claude in Chrome can drop right after a BankID login. After one timeout, read the page through computer-use instead (`app_screenshot`, `app_ax_find`; a browser is read-only there), which read the whole form.
- **[ask-last]** Before asking Alexander a fact, read dev, the plan, memory and the data; a question whose answer writes a column says which way the column reads, or a given answer gets written backwards.
- **[no-production]** A project that ships nowhere says `"production": "none"` and merges by `/one-ring`, no deployer. One with production has a deployer from day one, unless its host ships main with no database: `"production": "on-merge"`. Both are `/one-ring`'s "Projects without a database".
- **[guard-code-words]** The guard reads code it can't parse (a heredoc's Python, a node line after an unknown runner) as commands; a word built at run time counts as a hidden gh merge: a `$` word always, a plain glob only when it could match or names a guarded command. Heavy code: a script file.
- **[read-back]** A note of Alexander's with a negation or a relative ("not left aligned", "bigger", "above 13 inch") is read back as the exact look, with a number or a shot, before a builder starts; a misread costs commits and a wrong-way round.
- **[motion-qa]** The browser pane draws no frames (rAF 0), runs no smooth scroll, and `shot.mjs` freezes CSS animations at desktop widths, so anything animated or scroll-driven is checked by headless Chromium probes or with motion off, never by eye, and the smooth path goes to his phone look.
- **[next-dev]** Next 16 refuses a second dev server in one folder: a lane shoots with `next start` on its own port or works in its own worktree.
- **[links-live]** Every outbound link is fetched and its page title read before it ships; a 200 alone proves nothing (a lapsed domain can serve another site).
- **[layout-check]** QA runs `<design>/scripts/qa/page-scan.js` from the project's `public/qa/`; a project deletes its old `scripts/qa/layout-check.js`.
